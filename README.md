# Mikozora

An Android-first anime and donghua browser inspired by the source-based discovery, library and history idea in [Kotatsu Redo](https://github.com/Kotatsu-Redo/Kotatsu-Redo). Mikozora is an independent project; it does not include Kotatsu's code or manga parsers.

**Mikozora was previously called Moku.** The 0.12.0 rebrand kept the Android application ID and existing on-device storage identifiers as the legacy `app.moku.anime` and `moku.*` values. Mikozora 0.13.0 then introduced the project's permanent Android signing key. Because GitHub builds through 0.12.0 were debug-signed, Android cannot install a permanently signed release over them: uninstall the old copy once. Uninstalling removes private app data and in-app downloads, but files already exported to a chosen folder remain. Later permanently signed releases such as 0.20.0 use the same key and update signed 0.13.0 and newer installations in place.

## Features in 0.20.0

- **Watched checks in the Android player:** episodes you have already opened carry a ✓ and a dimmer label in the native player's episode rail, matching the browser player and series pages. The web layer flags watched episodes in the playlist it already sends the player, and the marks update as you move through a series with Previous, Next or the rail.

- **Update-download fix:** the in-app update checker's **Download update** action could silently do nothing on Android, because external links were restricted to the content source sites. Mikozora now also permits links to its own GitHub releases — the release page and the APK asset, and nothing else outside the source allowlist. If you are coming from 0.16.0 or 0.17.0, open the GitHub release page manually this once; the in-app download button works again from 0.18.0 onward.

- **Continue watching & watched progress:** Home's **Continue watching** rail lists series you are partway through — one tap plays the next unwatched episode, each card shows how far you have got (for example 7 of 12 watched) with a progress bar, and the × button removes a series from the rail. Opened episodes are marked **WATCHED** in episode lists and carry a check in the player's episode rail; Library cards show your progress instead of the status chip once you have started a title. Progress is tracked per title on this device from episodes you actually open, merged with your existing history; it records opened episodes, not playback position. Clearing watch history clears progress too, and until you have played something the rail keeps its previous Recently opened behavior.

- **In-app update checker:** Mikozora is installed from GitHub, so it now checks the project's GitHub Releases for a newer signed version when it opens (at most twice a day) and shows a dismissible banner with a direct link to the new APK. **Settings → About → App updates** shows when it last checked, offers a manual **Check**, and has a switch for automatic checks. Dismissing a version hides it until an even newer one appears; a failed check stays silent and simply retries later. The check only asks GitHub for the latest release — no account or analytics involved.

- **New app icon:** a torii gate beneath the morning star with the sun rising between its pillars — a proper adaptive icon that follows your launcher's shape, with a themed monochrome version on Android 13 and newer.

- **In-player episode navigation:** while an online episode is open, use **Previous** or **Next** below the video, or scroll the episode rail and tap an episode number. Mikozora finds the selected episode's servers without making you return to the series page; if that lookup fails, the current episode stays open and the player shows why. Episode changes use chronological episode order, update recent history, reset to the new episode's first available server, and disable Previous or Next at the ends of the series. The controls are below the video, so exit a third-party player's fullscreen mode to use them.
- **Permanent Android signing:** 0.13.0 was the first GitHub release signed with Mikozora's permanent key. A debug-signed 0.12.0 or earlier installation must be uninstalled once before installing a permanently signed release; after that transition, signed GitHub releases such as 0.20.0 update in place.

- **A new name:** Moku is now **Mikozora**. Only the name, wordmark and release/artifact naming change; your existing library, collections, history, downloads, settings and exported folder copies remain in place on an in-place update.

- **Browse filters:** in **Browse**, filter the catalog by **genre**, **release year** and **content** (all, safe only, or NSFW only), alongside the existing source and status filters. Genre uses each source's own genre listing — the same listing its detail pages link to — and year uses the watch sources' filter route; the WordPress-style donghua sources offer a genre parameter but no year listing, so a year filter reports them as unsupported instead of silently ignoring it. As with status, clear a keyword search to use genre/year filters, because source searches ignore them. Titles whose own metadata contradicts a filter are also dropped locally, and the results line says how many loaded titles are hidden by filters.
- **Age ratings:** every anime and donghua card shows an age-rating chip and, when known, its release year; detail pages show the rating beside the source and in the source-details facts. Ratings are normalized onto one PG-style scale (G, PG, PG-13, 16+, R, 18+) from whatever the source publishes (for example TV-14 becomes PG-13). Mikozora never invents a rating: sources often publish none on listing cards, and those titles are shown as **NR** (not rated) until a source provides one. A numeric source score is never displayed as an age rating.
- **Hide NSFW content:** **Settings → Content** has a separate switch that completely turns off NSFW content. When on, titles a source marks 18+ or with adult genres such as Ecchi or Hentai are hidden from Discover, the hero and trending rails, Browse and search results, the Library and History, and an adult-marked title cannot be opened (for example from an episode-update notice). Nothing is deleted — library entries, collections, history, downloads and folder files are untouched, and turning the switch off restores everything. The Browse content filter is independent and applies only while you browse. Sources do not label every title, so classification only covers titles they actually mark; it is not a guarantee that everything remaining is suitable for all ages. The preference is stored separately from your library and appearance settings.
- **Appearance:** in **Settings → Appearance**, choose Dark or Light and a Green, Blue, Purple, Pink or Amber accent. Choices apply immediately and are saved separately from your library, collections, downloads and update preferences. Fresh installs start with Dark and the Blue accent; any appearance you have already chosen is kept, and the original dark-green look remains available as the Green accent. Artwork and video are not color-filtered. The native online-player controls and Android system bars follow the selected appearance; the offline video player remains dark. Android 6–7 keeps a dark navigation bar because those versions do not support dark navigation icons.
- **Backup & restore:** in **Settings → Your data**, **Export** saves your library, collections, history, watch progress and preferences (appearance, content and update settings) to a single JSON file wherever you choose, and **Import** restores it later — on this device after a reset, or on a new phone — replacing the current data only after a confirmation that shows what the backup contains. Only Mikozora's own known stores round-trip through a backup, and downloaded video files are not included.
- **Mark watched by hand:** the circle button beside each episode, and **Mark watched** / **Mark unwatched** while selecting episodes, let you correct your progress without playing anything — for episodes watched elsewhere or opened by accident. Marking never invents history entries, unmarking also removes the matching entries from your history, and Continue Watching recalculates immediately.
- **Episode updates:** titles in Favourites or any personal collection are checked once per source/title, both when the app opens and periodically in the background (about every six hours when Android permits). The first successful check establishes a quiet baseline; later source-reported additions appear in **Updates**, with unread badges and optional Android notifications. Use **Check now** to request a manual check, even if automatic checks are off. The app asks for Android 13+ notification permission when needed; Settings has separate controls for automatic checks, Mikozora alerts and Android notification access. A network connection is required, Android may defer work, and force-stopping the app pauses background jobs until it is opened again. Source listings can change, disappear or report an episode before a playable server is available.
- Only titles assigned to Favourites or a personal collection are followed; titles merely saved under All titles are not. Removing a title from its last collection stops checks and removes its episode-update history, not its library entry, history, downloads or files. Re-adding it starts a fresh silent baseline. In the interest of avoiding false alerts when a source temporarily supplies a partial list, the checker announces higher-numbered episodes and new unnumbered episode links; it does not announce newly backfilled lower-numbered episodes. Source errors leave the previous baseline intact and are shown in Updates. At most the 500 most recent update entries are kept on the device. AnimeBash checks its own provided episode metadata, filters explicitly future-dated entries and does not invent a larger episode list from the series total.
- **Welcome and changelog:** on a fresh installation, Mikozora introduces the app and shows the release notes. On an existing installation, the changelog opens once after an update, then stays hidden until the next version. The user can reopen it under **Settings → What’s new**. Leaving before dismissing the screen shows it again next time. The small version marker is kept separately from the library, collections, history and downloads.
- Browse and search the ten chosen sources: **Anime** — AnimeSogo, AnimeSuge, Anikoto, Animerulz, Aniwaves and AnimeBash; **Donghua** — AnimeXin, NarulDonghua, DonghuaStream and DonghuaWorld. Sources has separate categories; Browse can show all sources, a category or one source. Open title details, search and sort episode lists, save titles and keep local history.
- Home has separate **Discover anime** and **Discover donghua** rails and a **Trending now** section using each source's weekly ranking (choose AnimeSogo or AnimeXin). Discover anime uses AnimeSogo's most-viewed listing; the recently updated rail remains separate.
- Series details show the source's status, reported episode count and aired/release dates when provided. AnimeSogo's “Currently Airing” and “Finished Airing” are also labeled Ongoing and Completed, with the original wording shown. Browse can filter source listings by Ongoing, Completed or Upcoming where a source supports it; unsupported or unreachable sources are reported. Aniwaves does not offer an Upcoming filter. Clear a keyword search to use status filters because sites may ignore status during searches. Listings and metadata may change or be missing at the source.
- **Library collections** are stored on this device. Previously saved titles stay in **All titles**; they are not automatically marked as Favourites. Tap the heart on a saved title to add/remove it from Favourites. Create collections in Library, then use **Add titles** to select from saved titles; you can rename or delete a custom collection. On a title's detail page, **Collections** assigns it to multiple collections and saves it to the library if necessary. Removing a title from the library also removes its memberships, but never deletes downloads; deleting a collection keeps its titles, downloads and folder files. Clearing the library in Settings clears memberships but keeps the empty collections.
- Play episodes in an isolated in-app video WebView, switch between source-provided mirrors, and move to the previous, next or any listed episode from the player's scrollable episode rail. AnimeXin protocol-relative mirrors are normalized instead of being silently omitted. An **Open original site** button remains available for the currently selected episode.
- **Android offline queue:** tap the download icon beside an episode, or choose **Select episodes** and select up to 50 at a time. All six Anime sources download identifiable English subtitle tracks only; AnimeXin retains its English/Indonesian choice and the other Donghua sites depend on the selected server. Choose a detected download server and an available video quality, or keep the Automatic/best defaults. Open **Downloads** to see progress, retry a failure, change its server, play completed episodes offline, or remove them.
- **Server and quality choices:** the dialog checks one episode in the chosen subtitle language. AnimeSogo's selectable mirror entries currently resolve to **MegaPlay SUB**; they are site mirror choices and may share the same underlying host. AnimeXin can offer **MediaFire**, **Dailymotion** and **OK.ru** when supported and reachable. The new sources can offer compatible **MegaPlay**, **EchoVideo** (Aniwaves), **Dailymotion**, or **OK.ru** mirrors, depending on the episode; other hosts may play in the video WebView but are not necessarily downloadable. HLS choices show the resolutions reported by the stream; fixed-file resolutions are labels reported by the source, not independently measured. Automatic HLS quality is capped at 1080p; an explicitly selected higher resolution may work when the device supports it.
- For a batch, choices are discovered using the first selected episode and rechecked for each episode just before download. If the selected server or exact quality is missing or unsupported, that episode fails rather than silently switching. Use **Change server** on a failed episode to choose again. For Anime sources, only identified English sidecar tracks are fetched, and only identified English HLS subtitle renditions are selected. If English is unavailable, the video can still download without English subtitles; if an offered English sidecar cannot be saved, the download fails rather than claiming success. AnimeXin files generally contain burned-in subtitles in the selected language.
- The queue uses AndroidX WorkManager and Media3 to persist requests and download progressive video or selected HLS renditions and their segments—not just a stream URL or playlist. Two resolver workers and up to two media downloads run concurrently. HLS audio and supported subtitle renditions are selected with Media3's download helper; Anime text selections are limited to identified English tracks.
- **Title-organized playable folder copies.** Select an Android folder in **Settings → Download location**. New downloads are converted inside the app, then saved as MP4 files in a subfolder named for each title, with saved subtitle sidecars alongside them. After checking the saved files, Mikozora removes the private copies and plays from the selected folder. Existing in-app downloads can be saved individually with **Downloads → Save to folder** (or **Save another copy** if already exported).
- The responsive browser preview demonstrates the interface and sources. **Downloads, folder copies and offline playback run in the Android app only.** Android contacts the chosen sites and video hosts directly; it does not depend on the preview server.

## Using an external video player

1. In Mikozora, open **Settings → Download location → Choose folder**. Choose or create a writable folder with Android's system picker. Some protected locations or storage providers may not allow folder access; Android may restrict selecting the root Downloads folder, in which case create and select a subfolder.
2. Download an episode normally, using any supported server/quality. When its in-app download completes, Mikozora queues a separate playable copy in a title subfolder—for example, `Selected folder / One Piece / One Piece - Episode 1 - … .mp4`. The Downloads page shows whether the copy is queued, saving, verifying, completed or failed. Conversion is performed one copy at a time. Mikozora reads the resulting video and sidecar files back and checks their size and SHA-256 hashes, and checks that the video contains readable audio and video tracks. Only after these checks does it switch the Downloads entry to folder-backed playback and remove the private media and sidecars. Verification and cleanup can take time; the private download remains if copying or verification fails.
3. For an episode already downloaded before choosing the folder, or exported with an older version, tap **Save to folder** (or **Save another copy** if already exported) on its Downloads card to create and verify a new copy in the title subfolder. Existing downloads are not silently migrated or deleted merely by installing this update. Tap **Open file** or open the MP4 from that subfolder in an external player. If that player does not automatically load captions, select the adjacent subtitle file from within the player.
4. Changing the selected root affects future copy jobs; jobs already queued keep their original destination. Existing exported files are **not moved or deleted**, even when saving a new copy. **Stop saving folder copies** prevents future automatic copies but does not cancel already queued jobs or delete files. If Android or the storage provider revokes access, choose the folder again.

The title subfolder is based on the displayed series title; characters unsafe for common storage providers are replaced and very long names are shortened. When a name has to be changed, a short, stable suffix helps keep different titles from being merged. A changed title from a source can result in a different subfolder. If a file already uses the intended folder name, rename that file and retry. Some providers may not support creating or listing subfolders; choose a different writable folder if copying fails.

During processing, the private cache, a temporary conversion file in app storage, and the folder copy may coexist, so allow enough free space for all three. Once verification and cleanup finish, the saved folder copy is the episode used by Mikozora; do not move, rename or delete it or revoke access if you want the Downloads entry to keep playing. If access is lost, restore access or re-download the episode. Removing an entry in Mikozora or uninstalling Mikozora does **not** delete your folder files; manage them separately with a file manager. Interrupted jobs resume when Android allows background work. If interruption occurs after cleanup has already started and the saved folder becomes unavailable, restore access to the saved files; the partially cleared private cache may no longer be playable. A partial destination file may need manual deletion after an interruption or if a provider refuses cleanup; existing user files are not overwritten.

MP4 export depends on the source format, the device's media codecs, Android's document provider and the external player's capabilities. Unsupported/DRM streams or an export with missing audio/video fail instead of being presented as complete. Some streams require re-encoding and take longer or use more storage. Exact output resolution can differ from a source-reported manifest label. Saved subtitle tracks are written as separate `.vtt` or `.srt` files: the preferred language uses the same base name as the MP4; additional tracks use language-suffixed names. Subtitle auto-loading varies by player and by how the file is opened. Burned-in subtitles remain in the video. Some in-stream or embedded caption renditions may not be copied into the exported MP4; when Mikozora detects such captions and cannot safely copy them, it retains the private download and reports this on the Downloads card instead of deleting the only known caption copy.

## Important limitations

- Offline downloading is **host-dependent**. Mirrors other than the compatible hosts above, DRM-protected videos, unavailable files, anti-bot challenges and some regional restrictions are not supported. Source layouts, host APIs, signed URLs and availability can change. Failed downloads are shown in the queue; retry or open the original site. AnimeBash returned HTTP 403 in a desktop test environment, although its API and a MegaPlay resolver worked in the Android emulator; a full Android download has not been verified. It can provide fewer episode links than its reported total, and Mikozora does not invent a partial source list.
- Subtitle languages and format depend on the source. New Anime downloads save only subtitle tracks identified as English; if English cannot be identified, no other language is substituted. Captions embedded in a video stream or burned into the image cannot necessarily be removed. AnimeXin's burned-in subtitles cannot be switched off or changed after downloading. No subtitles are manufactured by the app. Existing episodes and downloads already in progress are not modified: remove and re-download an episode to apply the new policy. Existing exported files remain until manually deleted; new folder copies of older AnimeSogo downloads include only identifiable English sidecars.
- Downloads can be very large and **may use mobile data**; there is no Wi-Fi-only setting in this version. Android battery/network restrictions, host timeouts or insufficient storage may interrupt downloads. Removing a download clears its private files when safe; older downloads can share cached stream data, so bytes still needed by another download are retained. Uninstalling or clearing app data removes private copies, but not the separately exported files.
- Mikozora is not feature parity with Kotatsu. There are no cloud sync, tracker integrations or installable extensions. Online history records that an episode was opened, not the exact playback position. Offline playback keeps a position on the device.
- Use sources and content you have the right to access. Mikozora is not affiliated with the source sites, Kotatsu or their video hosts.
- GitHub APKs through 0.12.0 are **debug-signed**. Starting with 0.13.0, release-publishing workflow runs use the permanent signing key configured through the secrets in [`docs/SIGNING.md`](docs/SIGNING.md); moving from a debug-signed installation to 0.13.0 or later requires one uninstall/reinstall, while later permanently signed releases update a signed installation in place. Requires **Android 6.0+** and an up-to-date Android System WebView. A native test harness on an Android 8 software emulator downloaded an AnimeSogo episode, saved its English captions and played it offline, then used the real folder picker to export the complete cached episode and subtitle while offline. FFmpeg decoded samples from the beginning, middle and end of the resulting MP4. Synthetic separate-audio HLS and progressive MP4 folder exports, failure cleanup and an external-player content-URI handoff were also exercised; repeated synthetic HLS cache-injection tests sometimes failed and their cause is unconfirmed. Folder conversions share the background queue and can delay other work. The emulator dropped most frames when trying real-time playback of the full-resolution episode—even for an independently remuxed reference—so smooth external playback of that episode is **not verified**. A separate short progressive-video fixture verified title-folder reuse for automatic and manual copies, separation for two titles, subtitle placement, sanitized-name collisions and cleanup of a failed copy using the Android 8 document provider. The app has been successfully tested on a physical Android device, including the WebView UI, online player, downloading and playback.

## Install the APK

Copy `Mikozora-v0.20.0-Android.apk` to an Android device and open it, or use:

```sh
adb install -r Mikozora-v0.20.0-Android.apk
```

Android may ask you to allow installs from your file manager. On Android 13+, notification permission lets Android show download progress and new-episode alerts in the notification shade. Granting it is recommended; episode updates still appear inside Mikozora if notification permission is denied. An APK update must be signed with the same key as the installed build to preserve local data; locally built debug APKs may have a different signing key. In particular, if Android reports a signature conflict when moving from 0.12.0 or earlier to a permanently signed release, uninstall the old copy first—this is the expected one-time signing transition and will remove private app data and in-app downloads. Signed 0.13.0 and later installations update in place.

## Build the Android project

Requirements: Node.js 20+, Java 17, Android SDK Platform 35 and Android build tools. Gradle downloads AndroidX Media3, WorkManager, OkHttp and jsoup from the configured repositories. The committed `android/app/src/main/assets/web/` already contains the built UI, so opening the `android` folder in Android Studio and building `debug` works without Node until the UI is changed.

After changing the web UI:

```sh
npm ci
npm test
npm run prepare:android
cd android
./gradlew assembleDebug
```

The local debug APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`. The included GitHub Actions workflow uploads a debug APK as the `Mikozora-Android` artifact for ordinary branch and pull-request runs, while also compile-checking the release-signing configuration with a throwaway CI key. A release-publishing run instead requires the four permanent signing secrets described in [`docs/SIGNING.md`](docs/SIGNING.md), builds and verifies a signed release APK, and publishes it to GitHub Releases automatically when `main` contains a project version that does not have a release yet, when a matching `vX.Y.Z` tag is pushed, or when the workflow is run manually from `main` with **Publish or replace the APK on the GitHub Release for this version** enabled. Release assets are named `Mikozora-vX.Y.Z-Android.apk`; ordinary pushes after that version's release exists do not overwrite it unless you use the tag or manual publish option. `npm run build` regenerates the scoped theme color rules from `src/style.css` using `scripts/generate-theme-css.mjs`; the original dark-green stylesheet and artwork/source badges remain untouched. For each subsequent release, update `APP_VERSION` and prepend the release notes in `src/releases.js`, update the versions in `package.json`, `package-lock.json`, and `android/app/build.gradle`, and increment Android `versionCode`. The version-consistency test checks these values so the changelog appears once for the new version.

## Browser preview

```sh
npm ci
npm run dev
```

Open the address printed by Vite. Its development-only proxy allows requests only to configured sources and artwork hosts. Android uses a narrowly allowlisted, on-device HTTP bridge for catalog/source pages. Video hosts run in a **separate WebView with no JavaScript bridge**; source HTML is parsed inertly. In-player episode changes pass through a native in-process callback to the trusted main UI, which resolves the selected episode before updating that same player. For offline media, host URLs are checked for HTTPS and public-address DNS, and Media3's network client checks redirects and refuses private-address connections.
